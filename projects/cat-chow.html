CAT-chow

A 2D pixel platformer built from scratch in Java. Play as Chao-chao, a lost cat navigating 7 unique stages filled with enemies, obstacles, and boss-like encounters — built entirely using Java's standard libraries.

View on GitHub →

Problem

Most beginner game projects rely heavily on existing engines, limiting understanding of how core systems actually work. I wanted to challenge this by building a complete game from scratch using only Java's standard libraries. The goal was to deeply understand game loops, rendering, collision systems, and AI behavior without relying on external frameworks.

Features Overview

7 Unique Stages
Each stage includes its own tilemap, music, enemy layout, and gameplay pacing.
Dynamic Power-Up System
Includes speed boost, double jump, air slash, and invisibility mechanics.
Enemy AI System
Multiple enemy types with distinct behaviors such as patrol, pursuit, and aerial tracking.
Game State & Save System
Persistent progression with save/load functionality and a structured state machine.
Stage 5 Mechanic Swap
Full gameplay transformation into an airplane mode with new controls and auto-scrolling.
Cutscenes & Ending Sequence
Narrative transitions between stages and a complete ending experience.

Tech Stack

Frontend / Rendering

Java Swing, AWT

Core Systems

Custom tile renderer, collision detection, camera system

Game Logic

Entity system, AI behavior scripts, game state machine

Other Tools

Custom sound engine, input handler, save/load system

How It Works

The game runs on a custom-built 60 FPS game loop, ensuring consistent updates and rendering.

Input Handling

Player inputs are captured and translated into movement and actions.

Game State Processing

A state machine manages transitions between menus, gameplay, and cutscenes.

Physics & Collision

Tile-based collision detection determines interactions with the environment.

Entity System

Enemies and player objects update independently with their own logic and stats.

Rendering Pipeline

A custom tile renderer draws the world, entities, and UI relative to a camera system.

A standout system is Stage 5, where the game dynamically swaps player physics, controls, and rendering behavior mid-game without breaking the main loop — achieved through clean separation of state and logic.

Future Improvements

  • Enhance enemy AI with more advanced behavior patterns and state transitions
  • Improve visual polish with animations, particle effects, and smoother transitions
  • Add more levels, boss mechanics, and progression systems
  • Optimize rendering and memory handling beyond Swing limitations
